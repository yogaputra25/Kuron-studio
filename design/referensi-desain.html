Masalah Referensi 3 Arah Token

Bikin Kuron terasa seperti app khusus translate manga

Tujuan dokumen ini: satu halaman berisi referensi nyata dari app sejenis, audit singkat layar sekarang, lalu tiga arah tampilan baru yang bisa dibandingkan berdampingan. Semua mockup memakai token --ks-* yang sudah ada di src/app.css — tidak ada warna, radius, atau tinggi kontrol yang dikarang baru.

01

Kenapa sekarang terasa seperti utility, bukan app translator

baca dari App.svelte baris 286–376
Header sekarang memuat 15 kontrol dalam satu baris — 4 pemisah vertikal ada di kode, tapi tak berlabel dan hilang di mobile sehingga header wrap 2 baris. Hasilnya: tidak ada yang menonjol, dan tombol destruktif (Hapus project) berdiri sejajar dengan tombol harian (Import file), hanya dijaga confirm() bawaan — tanpa undo.

15 kontrol, satu bobot

Hanya 2 dari 14 tombol dibedakan (Detect = primary, Hapus = danger); sisanya ghost seragam dan pemisah tanpa label. Mata tidak punya titik masuk, jadi setiap kali harus memindai dari kiri.

5 panel modal menutupi kerja

Batch, Glossary, Review, Provider, Diagnostics semuanya modal (fixed inset-0 di ui/Panel.svelte), dan EditorPanel sendiri fullscreen menutup grid. Tak ada satupun yang merespons Esc — jalan keluar satu-satunya klik × — dan pindah halaman berarti tutup-buka berulang.

0 agregat terlihat di layar utama

Badge status per kartu memang ada (StatusBadge), tapi kecil di footer kartu; ringkasan progres project hanya hidup di dalam modal Review — tidak terbaca sebagai alur.

Grid = satu-satunya navigasi

Mencari bubble tertentu berarti mengingat halaman berapa. Tidak ada daftar bubble yang bisa dipindai. Grid kosong (0 halaman) pun hanya teks petunjuk tanpa tombol aksi — melanggar aturan empty-state sendiri (App.svelte:470).

Detect semua = operasi buta

Tombol menunggu detectBatch seluruh halaman (±2 mnt/26 hlm): semua kontrol header disabled, tanpa progres, tanpa batal. Ironisnya event detect_progress sudah di-emit backend — tapi di-listener dengan callback kosong.

Alasan disabled hanya di tooltip

Batch mati tanpa provider, Ekspor PNG/PSD mati di mobile — alasannya cuma di title. Pola sistemik: user sentuh dan keyboard-only tak pernah tahu kenapa tombol mati.

i18n bocor di ≥10 titik

"Dibatalkan", "Detail", "Load models", "Lepaskan file untuk import…" tertulis langsung di komponen, lewat dari i18n.ts. Prinsip tiga bahasa jebol: user EN/ZH dapat campur aduk Indonesia.

Header ganda + kriptik

Select sudah berisi "Chapter 12 · 182", label "182 halaman" mengulanginya. RTL→, ◐, ID, Update tanpa label teks — hanya bisa ditebak lewat tooltip. Mockup arah A mempertahankan ketiganya apa adanya.

Dinding badge sukses prematur

26/26 TERDETEKSI cyan (14) merayakan setengah jalan: belum satu pun diterjemahkan. detected memakai cyan — warna teknis — sehingga "sudah dideteksi" terbaca "sudah beres".

Nama file tabrakan antar chapter

Impor zip menaruh "01.jpg IDLE" di sebelah "01.jpg TERDETEKSI" (18): chapter beda, nama sama, tak bisa dibedakan. Sort memakai path penuh tapi yang tampil basename — tabrakan tak terlihat sampai diklik. (Lihat issue #7.)

Bahasa berhenti di tengah jalan

Mode EN tetap menampilkan TERDETEKSI + "26 halaman" (16): statusLabel() ID-hardcoded, {count} halaman inline. Sebaliknya UI ID menampilkan "Retry page" (08). Bocor dua arah sekaligus.

Judul modal tiga standar

Providers/Glossary/Batch lewat $t, Diagnostics hardcoded "Diagnostics", Review memakai nama project ("kocak", 08). Lima modal, tiga konvensi judul.

Hapus baris sekali klik

Hapus provider / entri glossary langsung jalan tanpa confirm(); konfirmasi hanya ada di level project. Risiko kecil per baris, tapi tanpa pemulihan.

Error mentah menggeser header

Update gagal menempel String(e).slice(0,200) EN mentah di header (19) sampai tombol Hapus terpotong tepi. Error backend bocor ke layout — tanpa terjemahan, tanpa konteks, tanpa aksi.

Review: aksi salah label

"Retry page" di baris IDLE yang belum pernah dicoba (08) — seharusnya Translate. Lima tombol ekspor masih di atas lipatan; komentar kode sendiri mengakuinya.

Editor: toolbar campur + info developer

Satu baris berisi mode pandang + tool gambar + Detect + status "Tersimpan" yang menyamar jadi tombol (10); "Detect halaman ini" di pane menduplikasi tombol toolbar; daftar bubble "rect · 262×459" — dimensi piksel untuk developer, bukan translator.

02

Referensi nyata yang layak dipinjam

5 app · dipilih karena paling se-domain

Bukan moodboard estetika — ini app yang memecahkan masalah yang persis sama dengan Kuron. Kolom terakhir menyebut pola spesifik yang bisa diangkat, bukan sekadar "tampilannya bagus".

App Pola yang layak dipinjam Tautan
BallonsTranslator Desktop · Python · open source Sidebar kiri berisi daftar halaman + tombol aksi berikon berlabel (Gloss, Ri, x2) — menggantikan deretan tombol teks di header. Counter zero-padded 007/182 di judul window supaya posisi terbaca sekilas. Progress bar bertingkat: project-count di atas, progress per-tahap di bawah, jadi pipeline terbaca sebagai satu proses. Label provenance per teks — draft mesin, review LLM, dan hasil akhir disimpan dan ditampilkan terpisah, sehingga translator tahu mana yang belum dicek manusia. Bubble-bound auto layout: teks dipaksa muat pada geometri balloon asli. github.com/…
Aegisub Desktop · subtitle translation Translation Assistant: dua kolom sumber ↔ terjemahan berdampingan, bukan form bertumpuk. Keyboard-first — navigasi baris, terima, dan lanjut tanpa lewat mouse. Fokus pada satu baris aktif dengan konteks di sekitarnya tetap terlihat. Pola ini paling langsung bisa dipakai untuk daftar bubble Kuron. aegisub.org
youcomic · PixLate Web · comic translation Bubble fit preview — menampilkan apakah teks terjemahan muat di balloon asli sebelum diekspor. Ini fitur yang paling membedakan app "translate manga" dari app terjemahan biasa: batasnya bukan karakter, tapi geometri. Cleanup, layout, dan review dalam satu alur editor — tidak dipisah jadi aplikasi berbeda. pixlate.app
Crowdin · Lokalise Web · translation management Daftar string sebagai layar utama, bukan galeri. Satu baris = satu unit kerja, dengan kolom sumber, terjemahan, dan status di baris yang sama. Filter status (untranslated, needs review) sebagai cara utama menemukan pekerjaan, bukan menggulir galeri. crowdin.com
Figma · Blender Desktop · creative workbench Panel permanen, bukan modal — objek yang sedang dikerjakan selalu terlihat di samping kanvas. Status bar tipis di bawah membawa info posisi, zoom, dan selection tanpa memakan ruang atas. Rasio kanvas besar: alat menyingkir ke pinggir, bidang kerja dapat sebagian besar layar. figma.com

Tiga arah, dibandingkan berdampingan

tiap arah menampilkan layar berbeda

Ketiganya memakai token yang sama, jadi bedanya murni struktur — bukan palet. Bisa diambil terpisah: A dan C tidak saling menuntut, B adalah yang paling mahal.

A

Pipeline sebagai tulang punggung

layar: daftar halaman · perubahan paling murah

Header turun dari 15 kontrol jadi 6. Sebagai gantinya, satu baris pipeline lima tahap mengambil alih peran toolbar: dari PageStatus yang sudah ada (idle → detecting → detected → translating → translated), tiap halaman otomatis tahu berada di tahap mana.

Yang berubah
  1. 15 kontrol → 6. Yang tersisa: judul, pemilih project, counter, tema, bahasa, dan pemicu ⌘K.
  2. 6 tombol pindah ke ⌘K. Batch, Glossary, Review, Import, Bersihkan, Diagnostics tetap ada — hanya tidak lagi menempel di header.
  3. Pipeline bar jadi navigasi. Klik satu tahap untuk menyaring grid ke halaman di tahap itu.
  4. Status terbaca sebagai progres. Badge per kartu memakai PageStatus yang sudah ada, tanpa field baru.
  5. Hapus project keluar dari toolbar. Pindah ke menu project — destruktif tidak boleh sejajar dengan Import.
Biaya: rendah. Struktur data dan komponen tidak berubah; hanya perataan ulang header + satu bar baru.

C

layar: daftar bubble seluruh project · paling dekat app terjemahan

Unit kerja berpindah dari halaman ke bubble. Seluruh bubble project jadi satu tabel padat — sumber, terjemahan, status muat, dan status dicek dalam satu baris. Ini pola Crowdin dan Aegisub, dan satu-satunya arah yang menjawab "di mana bubble yang belum beres?" dalam satu detik.

Yang berubah
  1. Halaman bukan lagi satu-satunya navigasi. Bubble jadi baris; halaman jadi kolom.
  2. Filter menggantikan menggulir. "Belum terjemah" dan "Muat gagal" langsung menemukan pekerjaan tersisa.
  3. Status muat tampil sebagai kolom. Memakai textLayout yang sudah ada, tidak perlu pengukuran baru.
  4. Aksi massal di baris bawah. Tandai sudah dicek, terjemahkan yang tersaring, ekspor — untuk pekerjaan berulang.
  5. Klik baris → lompat ke halaman dengan bubble tersorot. Tabel dan kanvas saling menunjuk.
Kapan arah ini menang

Kalau keluhan sehari-hari adalah "saya tidak tahu mana yang masih bolong", arah ini jawabannya. Kalau keluhannya justru "menggambar bubble merepotkan", arah ini tidak membantu — B lebih relevan.

Biaya: sedang. Butuh query bubble lintas halaman dan tampilan baru, tapi komponen editor tidak disentuh.
04

Token yang dipakai mockup di atas

identik dengan src/app.css

Semua warna, radius, dan tinggi kontrol di dokumen ini diambil dari token yang sudah ada. Tidak ada nilai baru yang perlu ditambahkan ke app.css.

--ks-bg#0d0d10
--ks-surface#141418
--ks-surface-2#1a1a20
--ks-raised#22222a
--ks-line-strong#35353f
--ks-accent#ff6b5a · aksi
--ks-cyan#35e7f5 · teknis
--ks-success#5fd99a · muat/selesai
--ks-warn#ffc15e · perlu attention
--ks-danger#ff5c5c · gagal
Aturan bentuk yang dipakai
  • Satu tinggi kontrol: 28px (24px untuk yang padat). Tidak ada empat ukuran silih berganti.
  • Radius 6px untuk kontrol dan kartu, mengikuti --radius-card yang sudah ada.
  • Tanpa bayangan. Pemisahan lewat garis --ks-line, bukan shadow.
  • Tanpa gradien, tanpa emoji sebagai ikon.
Aturan warna
  • Koral hanya untuk aksi utama dan fokus keyboard.
  • Hijau = muat / selesai. Amber = perlu dicek. Merah = gagal.
  • Cyan untuk hal teknis: jumlah bubble, koordinat, ID.
  • Warna tidak dipakai untuk membedakan kotak satu sama lain.
Aturan teks
  • Nama tombol = aksi + objek: "Terjemahkan 118 halaman", bukan "Submit".
  • Kosong menawarkan aksi: satu kalimat penjelasan + tombol, bukan ilustrasi.
  • Error menyebut sebab dan jalan keluar.
  • Semua lewat i18n.ts (id, en, zh) — tidak ada string inline.
Langkah berikutnya. Arah A bisa langsung dikerjakan tanpa mengubah struktur data — hanya perataan ulang header plus satu bar pipeline. Arah C butuh query bubble lintas halaman. Arah B paling mahal dan paling mengubah rasa app.
